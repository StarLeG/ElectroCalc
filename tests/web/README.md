# Тесты веб-версии EngiCalc

Два слоя проверок. Каждый калькулятор проверяется против эталона, посчитанного
вручную или взятого из норматива (ПУЭ, ГОСТ, IEC, NIST), а не против кода сайта.

| Слой | Инструмент | Что проверяет | Где |
|---|---|---|---|
| Юнит | `node:test` (встроен в Node, зависимостей нет) | чистые функции расчёта и справочные таблицы | `unit/*.test.mjs` |
| Браузер | Playwright + Chromium | калькуляторы на собранных страницах: ввод, расчёт, вывод, формула, норматив | `e2e/*.spec.mjs` |

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install                        # один раз: ставит @playwright/test
npx playwright install chromium    # один раз: скачивает браузер (~115 МБ)

npm run test:unit                  # юнит-тесты, ~1 с
npm run test:e2e                   # сборка страниц + браузерные тесты, ~10 мин
npm test                           # оба слоя подряд
```

Выборочный запуск:

```bash
npx playwright test -c tests/web/playwright.config.mjs power          # один калькулятор
npx playwright test -c tests/web/playwright.config.mjs -g "запятая"   # по названию теста
npx playwright show-report playwright-report                          # HTML-отчёт после прогона
node --test --import ./tests/web/unit/setup.mjs tests/web/unit/rtd.test.mjs
```

`test:e2e` сначала собирает страницы (`tools/build-pages.mjs`): в репозитории
их нет, а тесты открывают именно то, что уйдёт на хостинг. Сервер для тестов
(`server.mjs`) Playwright поднимает сам на порту 4173, другой порт задаётся
переменной `ENGICALC_TEST_PORT`.

## Устройство браузерных тестов

Один файл на калькулятор, имя совпадает с адресом страницы: `/cable/` →
`e2e/cable.spec.mjs`. Типовой файл состоит из четырёх блоков, общие приёмы
вынесены в `e2e/helpers.mjs`:

- **`describeCases`** — параметризованные сценарии расчёта, от 3 до 5 на
  калькулятор. У каждого в комментарии записан ход ручного расчёта.
- **`expectFormulaPanel`** — показанная формула и ссылка на норматив
  соответствуют тому, как калькулятор на самом деле считает.
- **`describePlaceholder`** — число на странице до первого расчёта совпадает
  с тем, что калькулятор выдаёт по тем же исходным данным.
- **`describeInputValidation`** — пустое поле, буквы, отрицательное число, ноль
  там, где он даёт деление на ноль, запятая вместо точки, очень большое число.
  Ввод идёт с клавиатуры, как у человека.

Сквозные проверки собраны в `e2e/ui.spec.mjs` (нет сырых ключей перевода на
обоих языках, у каждого поля есть подпись, сброс, смена языка) и
`e2e/offline.spec.mjs` (страница работает без сети после первого визита).

### Допуск

Сверяется отображаемое, уже округлённое число. Допуск — большее из двух:
половина единицы младшего показанного разряда (ровно столько вносит округление)
и 0.1 % от эталона. Для сверки с нормативными таблицами, где модель заведомо
приближённая, используется `expectWithinPercent` с явным процентом.

### Известные дефекты

Тест, который воспроизводит найденную ошибку сайта, помечен `knownDefect(...)`
(в браузерных тестах — `test.fail()`). Пока дефект есть, прогон зелёный, а в
отчёте у теста висит аннотация `known-defect` с описанием. Когда ошибку
исправят, тест «неожиданно пройдёт» и упадёт с просьбой снять пометку: так
исправление не останется незамеченным.

Список дефектов — в HTML-отчёте (аннотация `known-defect` у теста) или поиском
по коду: `grep -rn "knownDefect\|defect:" tests/web`.

## Как добавить тест

1. Посчитайте эталон вручную или найдите его в нормативе и запишите ход
   расчёта комментарием рядом со сценарием.
2. Добавьте сценарий в `cases` нужного файла или новый файл `e2e/<раздел>.spec.mjs`
   по образцу `e2e/power.spec.mjs`.
3. Если тест падает, сначала убедитесь, что ошибка не в эталоне. Только потом
   помечайте его как известный дефект и описывайте, что именно не так.
