# Редактор электрических схем

Раздел «Редактор схем» — интерактивный редактор принципиальных схем (тип Э3) с режимом
эмуляции постоянного тока. Без внешних зависимостей и без сборки: обычные ES-модули.

## Модули

```
web/js/
├── schematic-model.js     Модель схемы, геометрия выводов, netlist, форматирование СИ
├── circuit-sim.js         MNA-солвер рабочей точки (DC)
├── schematic-presets.js   Встроенные схемы-заготовки
├── schematic-editor.js    Канва, палитра, свойства, эмуляция, экспорт
├── gost-schematic.js      Библиотека УГО по ЕСКД (UMD, глобальный GostSchematic)
└── circuits.js            Готовые схемы-примеры для страниц NE555 и ОУ
```

## Ключевое правило геометрии

`PIN_OFFSETS` в `schematic-model.js` обязан совпадать с координатами, которые
`gost-schematic.js` регистрирует через `_reg()`. Расхождение приводит к тому, что провода
не доходят до концов УГО, а солвер принимает вывод за землю и молча считает чушь.

Отсюда следуют неочевидные вещи:

**Все выводы всех типов лежат в узлах сетки 5 мм** — иначе провод не сходится с концом
УГО, а элемент нельзя аккуратно поставить рядом с соседним.

| Элемент | Особенность |
|---------|-------------|
| `vsource` / `isource` | Выводы **горизонтальные** (`p` слева). Вертикальный источник — это `rotate: 90` |
| `inductor` | Шаг выводов 20 мм, как у резистора (±10). Прежний расчёт `span + 6` давал ±11 — мимо сетки |
| `ground` | Рисуется с `lead: 5`; по умолчанию стойка 6 мм, и вывод уходит с сетки |
| `npn` / `pnp` | База (−10, 0), коллектор (5, −10), эмиттер (5, 10). Коллектор и эмиттер отходят от базы строго под 45° и приходят прямо в узел — без излома |
| `opamp` | Выводы на ±15 мм по X (box 20×20 + вывод 5 мм), имена `inv` / `non` / `out` |
| `diode`, `led`, `zener` | Выводы называются `a` и `k` (анод/катод), не `a`/`b` |

Два теста в `tests.html` стерегут это: `Pin names match pin geometry for every type`
и `Every pin offset lands on the 5 mm grid`.

## Модель данных

```javascript
{
  version: 1,
  grid: 5,                       // мм
  components: [
    { id: 'R1', type: 'resistor', x: 70, y: 40, rotate: 90, value: 10000, props: {} }
  ],
  wires: [
    { id: 'w1', points: [[30,50],[30,30],[70,30]], a: null, b: null }
  ]
}
```

Номиналы всегда в основных единицах СИ (Ом, Ф, Гн, В, А) — приставки появляются только
при выводе через `formatSI()`.

### Netlist

`buildNetlist()` объединяет union-find'ом все совпадающие точки: точки одного провода —
один проводник, совпадающие координаты — один узел. Сравнение координат **точное**
(с округлением до 0,01 мм), а не с округлением к шагу сетки: округление сливало бы
в один узел выводы, отстоящие меньше чем на полшага.

Отдельно обрабатываются **тройники**: точка, попавшая на середину чужого провода,
соединяется с ним. Без этого отвод, бро­шенный на шину питания, висел бы в воздухе —
а это самое естественное действие при черчении. Простое пересечение так не соединяется:
у него в точке пересечения нет вершины, что и соответствует правилу ЕСКД «крест без точки».

Опорный узел `GND` — объединение **всех** элементов «земля», их может быть несколько.
Остальные узлы получают имена `N1`, `N2`, … в порядке появления.

## Солвер (circuit-sim.js)

Модифицированный узловой анализ. Возвращает структуру:

```javascript
{
  ok: true,
  nodeVoltages: { GND: 0, N1: 12, N2: 6 },
  branches:     { R1: { u, i, p, dir, type } },
  pinCurrents:  { 'R1.a': 0.0006, 'R1.b': -0.0006 },
  wireCurrents: { w1: { i: 0.0006, dir: 1 } },   // dir: +1 — по points, −1 — навстречу
  warnings: []
}
```

### Знаки

Пассивная система знаков: `i` положителен, когда течёт **внутри** элемента от первого
вывода ко второму (`a→b`, `p→n`, анод→катод), `u = V(первый) − V(второй)`.
Поэтому `P = u·i > 0` — элемент потребляет, `P < 0` — отдаёт. У исправного источника
питания ток и мощность отрицательные — это норма, а не ошибка.

### Модели элементов

| Элемент | Модель в статике |
|---------|------------------|
| Резистор, лампа | `g = 1/R` |
| Конденсатор | разрыв (`G_OPEN = 1e-12`) |
| Катушка | перемычка — **отдельное неизвестное «ток ветви»**, не проводимость 1e6 |
| Замкнутый ключ | перемычка (так же через ток ветви) |
| Источник ЭДС | дополнительное уравнение `Va − Vb = E` |
| Источник тока | `I[p] -= J; I[n] += J` (внутри источника ток идёт `p→n`) |
| Диод / LED | кусочно-линейно: закрыт — `G_OPEN`, открыт — `Vf` последовательно с `R_ON = 10 Ом` |
| Стабилитрон | плюс ветвь пробоя при `|u| > Vz` |
| Транзистор n-p-n / p-n-p | Эберс — Молл: два кусочно-линейных перехода и управляемый источник тока |
| Операционный усилитель | идеальный: Uвых = K·(Uнеинв − Uинв) с ограничением по шинам питания |
| Оптопара | светодиод на входе, источник тока `CTR·Iсд` на выходе с ограничителем насыщения |
| Тиристор, симистор, динистор | отпирание по току управления и напряжению включения, защёлкивание в пределах расчёта |
| Катушка реле, контактора | резистор; признак срабатывания по напряжению на катушке |
| Контакт замыкающий, размыкающий | идеальная перемычка либо разрыв, состояние берётся у «своей» катушки |

### Операционный усилитель

`value` — коэффициент усиления K (по умолчанию 10⁵), `props.vcc` и `props.vee` — шины
питания (±15 В). Питание задано **свойствами, а не выводами**: так работает и однополярное
включение (например 0…5 В), и не нужно рисовать питание на схеме.

Выход — идеальный источник напряжения относительно общего провода, поэтому ему выделено
отдельное неизвестное «ток ветви». В линейном режиме строка системы задаёт
`Uвых − K·(Uнеинв − Uинв) = 0`, в насыщении — `Uвых = Uпит`. Режим определяется по
предыдущему приближению и участвует в общей итерации вместе с диодами и транзисторами.

### Оптопара

Четыре вывода: `a`, `k` (светодиод) и `c`, `e` (фототранзистор). `value` — коэффициент
передачи тока CTR (0,5 для типовой транзисторной оптопары), `props.vf` — отпирание
светодиода (1,2 В), `props.vsat` — напряжение насыщения выхода (0,2 В).

Вход — обычный кусочно-линейный светодиод. Выход — источник тока `Iк = CTR·Iсд`,
управляемый напряжением на светодиоде, плюс **ограничитель насыщения**: диод, включённый
«эмиттер → коллектор» с порогом −Uкэ.нас. Пока нагрузка позволяет, ограничитель закрыт и
выход работает источником тока; когда Uкэ пытается упасть ниже Uкэ.нас, ограничитель
открывается и забирает избыток. Это тот же приём, что диод база-коллектор в модели
транзистора, и он так же обеспечивает непрерывный переход между областями.

Развязка получается сама собой: между сторонами нет ни одной общей ветви, связь только
через управляемый источник. Проверено тестом — изменение выходного питания с 12 на 30 В
не меняет ток светодиода ни на бит.

Оговорка: у решателя один опорный узел, поэтому обе стороны схемы должны иметь путь к
`GND`. Изолированную сторону без своей «земли» удержит только фоновая проводимость `GMIN`,
и её абсолютный потенциал окажется произвольным — на токи это не влияет, но узловые
напряжения такой стороны читать бессмысленно.

### Тиристорное семейство

| Тип | `value` | Свойства |
|-----|---------|----------|
| `scr` (тиристор) | падение в открытом состоянии | `igt` — ток отпирания, `on` — открыт принудительно |
| `triac` (симистор) | падение в открытом состоянии | `igt`, `vbo` — напряжение включения, `on` |
| `diac` (динистор) | напряжение включения | `vt` — падение в открытом состоянии |

Приборы **защёлкиваются в пределах одного расчёта**: сработав на какой-то итерации, они
остаются открытыми до конца. Без этого напряжение после отпирания падает ниже порога,
прибор «выключается», и итерация зацикливается.

Ток управления вычисляется, **только если переход управляющего электрода уже был открыт**
при построении текущего приближения. Иначе на нём стоит напряжение разомкнутой цепи, и
формула даёт фиктивные амперы — на первой же итерации тиристор отпирался сам собой даже
с гасящим резистором в 10 МОм.

Запирание не моделируется: реальный прибор закрывается, когда ток падает ниже тока
удержания, а это событие во времени.

### Реле и контактор

Катушка (`relay`, `contactor`) в статике — резистор; `value` — сопротивление обмотки,
`props.upick` — напряжение срабатывания. Контакты (`contactNO`, `contactNC`) ссылаются на
свою катушку через `props.coil`; если ссылка не задана, берётся первая катушка в схеме.

Каждому контакту выделяется ветвь **независимо от состояния**: замкнутый описывается
уравнением `Ua − Ub = 0`, разомкнутый — уравнением `i = 0`. Состояние меняется между
итерациями, а размер матрицы обязан оставаться постоянным.

Схемы с самоблокировкой статический расчёт покажет обесточенными: у него нет памяти,
и итерация от нуля приходит в устойчивое состояние «катушка не сработала».

### Биполярный транзистор

Параметры задаются в панели свойств: `value` — коэффициент передачи тока β,
`props.vbe` — напряжение отпирания перехода база-эмиттер (0,7 В),
`props.vsat` — напряжение насыщения коллектор-эмиттер (0,2 В).

Модель — упрощённый Эберс — Молл: **два** кусочно-линейных перехода (база-эмиттер и
база-коллектор) плюс источник тока, управляемый напряжением:

```
Iб = Iбэ + Iбк
Iк = βF·Iбэ − (1 + βR)·Iбк
Iэ = Iб + Iк
```

Порог перехода база-коллектор намеренно занижен ровно на `vsat`
(`vfc = vbe − vsat`): в глубоком насыщении `Uкэ = Uбэ − Uбк ≈ vbe − vfc`, то есть
заданное напряжение насыщения получается само собой, без отдельной ветви.

Так сделано не для красоты. Первая версия переключала коллекторную ветвь между
«активный режим» и «насыщение» по условию `Uкэ < Uкэ.нас` — и на транзисторном ключе
итерация зациклилась между двумя режимами, а солвер вернул усреднённый результат,
в котором **нарушался закон Кирхгофа в узле коллектора** (`Uкэ` выходило отрицательным).
У модели с двумя переходами разрывного перехода между областями нет: `Iбк` нарастает
плавно, и области перетекают одна в другую.

Область работы (`branches[id].region`) выводится из состояния переходов:
закрыт база-эмиттер — `cutoff`, открыт только он — `active`, открыты оба — `sat`.
В результатах для транзистора: `u` = Uкэ, `i` = Iк, `p` = Uбэ·Iб + Uкэ·Iк,
плюс `ib`, `ie`, `vbe`, `region`.

Обратный коэффициент βR зафиксирован в константе `BETA_R = 1` и в интерфейс не вынесен.
Внимание при правке стампов: сам диод база-коллектор тоже вносит ток в узел коллектора,
поэтому управляемый источник несёт **βR·Iбк**, а не (1+βR)·Iбк — иначе терминальный ток
коллектора разойдётся с формулой на величину Iбк.

Идеальные перемычки принципиально нельзя вносить проводимостью вроде 1e6 См: рядом
с резисторами в мегаомы это разрушает обусловленность матрицы, и «ток» через них
превращается в усиленный шум округления.

Нелинейные элементы решаются итерациями по состояниям переходов. Если состояния
продолжают перещёлкиваться, шаг демпфируется (коэффициент только уменьшается) — иначе
цепь со светодиодом зацикливается между «открыт» и «закрыт». Несходимость за 100 итераций
не роняет UI, а возвращается предупреждением `editor.warn_no_convergence`.

Вырожденные случаи (нет земли, вырожденная матрица, пустая схема) возвращают
`{ ok: false, error, messageKey }` — ключ i18n, а не готовый текст.

## Редактор

| Действие | Как |
|----------|-----|
| Поставить элемент | Клик по палитре, затем по канве |
| Провод | Кнопка «Провод» или `W`, затем клик по началу и по концу |
| Выделить | Клик по элементу или проводу |
| Переместить | Перетаскивание |
| Повернуть | `R` или кнопки в панели свойств |
| Удалить | `Del` / `Backspace` |
| Отменить / повторить | `Ctrl+Z` / `Ctrl+Y` |
| Снять инструмент | `Esc` или правая кнопка |

Горячие клавиши активны **только когда открыта страница редактора** — иначе `Ctrl+Z`
перехватывался бы на всех калькуляторах.

Концы провода прилипают к выводу компонента в радиусе 3,5 мм, иначе — к узлу сетки 5 мм.

### Режим эмуляции

Переключатель «Эмуляция» делает канву доступной только для чтения и запускает `solveDC`:

- по проводам с ненулевым током бегут штрихи, скорость пропорциональна `|I|`;
- в середине ветви — стрелка направления;
- у каждого двухполюсника — `U`, `I`, `P` с приставками СИ;
- клик по узлу закрепляет/снимает пробник напряжения;
- при `prefers-reduced-motion: reduce` бегущие штрихи отключаются, стрелки остаются.

### Хранение и экспорт

Автосохранение в `localStorage` (ключ `engicalc-editor`, запись отложена на 400 мс).
Экспорт: JSON, SVG и PNG. PNG строится отрисовкой SVG на `<canvas>`; перед экспортом
цвета из переменных CSS подставляются явными значениями, иначе автономный файл получится
без стилей.

## Схемы-примеры (circuits.js)

Девять схем для страниц NE555 и ОУ строятся той же библиотекой УГО.

**Правило файла: координаты выводов не пишутся руками.** Любая связь строится от
`s.pin(ref, name)` — тогда провод не может промахнуться мимо вывода. Раньше координаты
были набраны вручную и разошлись с реальной геометрией: во всех девяти схемах провода
не доходили до выводов, встречались диагональные связи, а «повторитель напряжения» имел
заземлённый вход.

Автоматически проверяемые инварианты: все выводы подключены, все звенья ортогональны,
точки соединения только там, где сходятся три и более проводника.

## Тесты

`web/tests.html` — открыть в браузере. Помимо расчётных формул проверяются:

- делитель напряжения, последовательное и параллельное соединение, закон Кирхгофа;
- цепь со светодиодом (`Vf` и ток) и обратно включённый диод;
- источник тока, стабилитрон в пробое, конденсатор как разрыв, ключ;
- транзистор во всех трёх областях (активный режим, насыщение, отсечка), влияние β
  и `vbe` на результат, зеркальность p-n-p, закон Кирхгофа в узле коллектора;
- вырожденные случаи возвращают структурированную ошибку, а не исключение;
- имена выводов совпадают с геометрией для всех типов;
- все пресеты решаются, их связи ортогональны и лежат на сетке;
- JSON round-trip не меняет ни модель, ни результат расчёта.

## Добавление нового компонента

1. Тип в `COMPONENT_TYPES` и смещения в `PIN_OFFSETS` (`schematic-model.js`).
2. Префикс позиционного обозначения в `REF_PREFIXES`.
3. Ветка отрисовки в `drawComponent()` (`schematic-editor.js`).
4. Модель в `solveInternal()` (`circuit-sim.js`), если элемент участвует в расчёте;
   иначе `simulated: false`.
5. Тип в `PALETTE` и ключи `editor.c_<тип>` в `I18N` (`core.js`, обе локали).
